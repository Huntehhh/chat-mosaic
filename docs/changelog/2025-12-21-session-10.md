## Fixed

### Error Messages Persisting Across Chats
- **Problem**: "Error running Claude: The operation was aborted" appeared in new chats after session switching
- **Root Cause**: `_handleProcessError` and `_handleProcessClose` used `_sendAndSaveMessage` which saved errors to conversation JSON files
- **Fix**: Changed to `_postMessage` so errors display but don't persist; Added `_intentionalKill` flag to suppress expected errors during session switch
- **Files**: `src/extension.ts` lines 993-1037, 1544-1556, 2897-2900, 3247-3249

### Legacy Errors Still Appearing
- **Problem**: Conversations saved before fix still contained error messages
- **Fix**: Added filter in `_presentLoadedConversation` to remove error messages matching patterns: "operation was aborted", "Expected message type", "Claude process"
- **File**: `src/extension.ts` lines 3385-3398

### Chat Name Showing File Path
- **Problem**: After loading CLI conversation and clicking "New", new conversation inherited old chatName (often a file path)
- **Root Cause**: `_newSession()` didn't reset `_chatName` field
- **Fix**: Added `_chatName = 'Claude Code Chat'` reset and webview notification in `_newSession()`
- **File**: `src/extension.ts` lines 1566-1587

### Invalid ChatNames From Previous Bug
- **Problem**: Some conversations had file paths saved as chatName from previous sessions
- **Fix**: Added validation to reject chatNames containing `:\`, `/.claude/`, or starting with `/`; Falls back to first user message
- **File**: `src/extension.ts` lines 3428-3432

### ProcessManager Verbose Logging During Kills
- **Problem**: Console flooded with "Claude process error" messages during intentional session switches
- **Fix**: Reordered `kill()` to clear `_currentProcess` BEFORE abort; Moved logging inside the check so handlers return early silently
- **File**: `src/services/ProcessManager.ts` lines 253-282, 386-392

## Changed

### Mod 2.4: Wire ConversationManager Service

**Added unified presentation layer** (`_presentLoadedConversation`):
```typescript
private _presentLoadedConversation(options: {
  messages: Array<{ timestamp: string; messageType: string; data: any }>;
  sessionId?: string;
  startTime?: string;
  source: 'internal' | 'cli';
  stats?: { totalCost: number; totalTokensInput: number; totalTokensOutput: number };
  chatName?: string;
  pagination?: { total: number; pageSize: number; startIndex: number };
}): void
```

**Refactored load methods**:
- `_loadConversationHistory()` - Now reads JSON, calls presentation layer (~35 lines, was ~130)
- `_loadCLIConversation()` - Now uses ConversationManager.loadJSONLConversation() + presentation layer (~60 lines, was ~80)

**Updated pagination support**:
- `_cliParsedMessages` type changed from `{ type, data }[]` to `{ timestamp, messageType, data }[]`
- `_loadMoreCLIMessages()` now converts to webview format when sending

**Added ConversationManager initialization**:
```typescript
this._conversationManager = new ConversationManager(this._context, {
  onConversationSaved: (filename) => console.log(`[ConversationManager] Saved: ${filename}`),
  onConversationLoaded: (messages, sessionId) => console.log(`Loaded ${messages.length} messages`),
  onError: (message) => this._postMessage({ type: 'error', data: message })
});
```

  if (msg.messageType === 'error') {
    const errorText = typeof msg.data === 'string' ? msg.data : '';
    if (errorText.includes('operation was aborted') ||
        errorText.includes('Expected message type') ||
        errorText.includes('Claude process')) {
      return false;  // Filter out
    }
  }
