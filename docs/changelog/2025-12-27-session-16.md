```typescript
if (thinkingMode && thinkingIntensity !== 'disabled' && thinkingIntensity !== 'think') {
    let thinkingPrefix = '';
    switch (thinkingIntensity) {
        case 'think-hard': thinkingPrefix = 'think hard: '; break;
        case 'think-harder': thinkingPrefix = 'think harder: '; break;
        case 'ultrathink': thinkingPrefix = 'ultrathink: '; break;
    }
    if (thinkingPrefix) actualMessage = thinkingPrefix + actualMessage;
```

## Phase 4: MCP Terminal Restart Debugging

### Changed: `src/extension.ts` - `_openMCPTerminal()`

Added extensive logging and fixed stale panelId issue:

```typescript
// Capture panelId at terminal open time (was using stale value at close time)
const capturedPanelId = this._requestingPanelId || this._activePanelId;

// Pass captured values to restart handler via closure
const disposable = vscode.window.onDidCloseTerminal(closedTerminal => {
    if (closedTerminal === terminal) {
        disposable.dispose();
        this._restartBackgroundProcessForMCP(capturedPanelId, sessionId);

});
```

## Open Loops

### Known Issues - MCP Not Persisting

**Symptom**: User disables MCPs in /mcp terminal, but our app's Claude session still has MCPs enabled.

**Investigation Progress**:
1. Process restart logic verified working
2. Issue persists even after full VS Code restart
3. Suspect `--resume SESSION_ID` caches MCP state in session file

**Hypothesis**: When using `--resume`, Claude may reload MCP config from session's saved state, not from `~/.claude.json`. The terminal works because it spawns a fresh interactive session.

**Potential Fixes to Try**:
- Use `--mcp-config` flag to force reload
- Don't use `--resume` for first message after MCP changes
- Check if session files store MCP state
